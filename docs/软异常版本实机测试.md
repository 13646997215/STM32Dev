# 软异常版本：实机测试步骤

## 当前交付

固件：`build/Debug/F401_COURSE.elf`；PC 上位机从迁移包根目录的 `03-Open-Monitor.cmd` 启动。先关闭旧上位机，重新启动以加载新的诊断代码。Debug 与 Release 均已编译；这里统一使用 Debug。源码和上位机必须来自同一工程版本。

## 上电和下载

1. 断开两个电机的 12 V 动力电源，控制板保持适当供电。此前 RESET 曾使电机高速转动；下载、复位和调试暂停前都先切断电机 12 V。不要在通电时更换接线。
2. VS Code 打开当前 F401_COURSE 工程，点击生成，选择该工程的 ST-LINK 调试配置下载 Debug 程序。不要使用其他目录的旧 ELF。开始运行后先保持动力断开，打开上位机并选择蓝牙串口，以 115200 8N1 连接。
3. 确认无线遥测持续刷新，IMU age 较小、手动转动 IMU 时 Pitch/Yaw 跟随变化，且当前无故障。将车和 IMU 放在计划的平坦起点；短按 PA0 时程序会将当前 Pitch 作为本轮零位，避免在斜面或晃动时启动。
4. 实车装配检查完成后，再连接电机 12 V；首次先架空双轮并保留足够空间，准备能够迅速切断 12 V 的实体开关。确认电机停转、方向和接线与实际车体相符。

## 测试和记录

1. 开始记录原始帧或录屏。短按并松开 PA0 启动默认统一流程。观察车体和上位机：阶段、Pitch、左右 PWM 与 FG、IMU age、告警，以及是否按预期运动。用 STOP 可主动结束；收到 ACK 和遥测归零后，仍需观察轮子确实停止。
2. 架空检查通过后，按现场条件进行低风险实车调试，再完整记录一次自主流程。若发生异常，记录发生时的阶段和实际动作，导出本轮 CSV，保留原始帧和录屏。坐标是 FG 和姿态推算；存在方向假设、打滑及传感器误差，不能作为外部定位或比赛成绩证明。
3. 关键变化：单次 FG 异常只丢弃该区间位姿脉冲并告警，不再立即锁存 FEEDBACK；该轮位置标记为不可信。超时和统一流程返回距离异常只告警，并不代表按时到达。IMU 数据过期、无效或倾角超限时 PWM 置零等待，恢复后才可能继续；告警可保留，检查当前 IMU age 和实际动作。若任务条件一直不满足，流程可能停留在当前阶段，不能保证一定完成。
4. 蓝牙断开或上位机关闭时 AUTO 可能继续，无法依赖 STOP 指令作为唯一制止方法。现场需要随时能够独立切断电机电源。结束后先断开 12 V，再暂停调试、复位或更改接线。

## 任务 6 的边界

PA0 默认启动 `PROFILE_BALANCE_RETURN`，第一次平衡后返回，不等待第二次加重；不能称其已自动完成任务 6。`PROFILE_REWEIGHT` 是另一个开始前选定的分支，会等待扰动再平衡。任务 5 和 6 的现场衔接及第二次加重规则需按课程要求确认，独立分支的实车效果尚未验证。

软件测试和编译不能证明实车安全、能够完成任务或满足规定的高度与计时；保留现场记录并测量实际结果。
