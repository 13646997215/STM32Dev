# 换向中点试验版：使用和回退

基线为 Git 提交 `29caf26`。本版仅为台架及低风险实车试验，尚未进行硬件验证，不保证任务完成或抗振荡。

## 工作方式

1. 自主统一流程处于 BALANCE/HOLD 时，先维持 Pitch PID。检测线速度指令由正变负或由负变正，在两次变化时分别记录当前位置估计 x。它是**指令换向时刻**，并非独立测得的车轮实际转折点。
2. 两点间隔为 0.02–0.50 m 时取平均值为候选中点。机器人以线速度目标不超过 0.015 m/s 的指令向该点移动；距离估计进入 0.01 m 后限制 PID 线速度目标在 ±0.015 m/s。速度目标受电机死区和负载影响，不能保证实际速度等于目标。
3. FG 数据超限、运行中长期无新鲜 FG、里程更新无效或 IMU 不可用时丢弃中点，重新采集；FG 相关情况只告警并退回原 Pitch PID，不因此宣称位置正确。两次换向不足或跨度不合理也继续原 PID。来自更早异常的全局 pose_valid 可继续为 0；中点仅依赖最近没有检出异常的相对 x 变化。
4. 单路 FG 无独立方向，方向按控制指令假设；滑动、惰行、未检测到的错误脉冲都会影响估计。绝对位置和候选中点不具备外部定位精度。长时间等待不会被当作任务成功；移动到中点时暂不累积平衡成功时间。
5. 稳定区内的 PID 从检测到超过 `stable_rate_dps` 的角速度时继续响应；方向反转仍保留电机低速和最少约 200 ms 的换向等待，因此不能保证瞬时反转。

## 测试

- 保持现场能独立切断 12 V，断开动力后下载并复位；之前复位时电机可能高速转动。先架空核验轮向，再在低风险条件下实车测试。
- VS Code STM32Cube 实时监视添加 `g_course.mission.midpoint.phase`、`g_course.mission.midpoint.target_x`、`g_course.position_epoch`：phase 0=采集中/退回 PID，1=前往候选中点，2=限制速度的 PID 微调。epoch 增加表示里程可靠性事件导致重新采集；target_x 是估计值。
- 记录视频、原始帧和 CSV；观察翻板、反向、phase 和警告。如果持续靠近边缘、轮子失控或振荡变大，现场手动停止并切断动力。CSV 不包含 midpoint phase，请另录屏或截图；不以目标坐标判断真实位置。
- PID 参数仍为 P=.006 I=.0003 D=.012；上位机设置与 flag 覆盖注意事项见 `平衡PID整定与测试.md`。

## 回退

若实测效果不佳，告知开发者回退试验提交；保留基线 `29caf26`。使用 Git revert 生成回退提交，不覆盖新的 CSV 或用户资料；回退源码后需重新编译并由现场操作者在断开 12 V 后下载。不得把 Git 回退误认为设备固件已经恢复。
