## 0. 范围与已确认决策

任务 1–6 **验收时不允许换代码**，因此只实现**一条流程**；用户确认"任务 1 被任务 2 覆盖"，即每次运行都是：

> 桌面起步 → 重定义 IMU 基准 → 原地转向对准板方向 → 前进上板 → Pitch PID 找平衡 → 平衡保持 10 s（LED 亮）→ 后退下板回到桌面 → 停车完成

|---|---|---|
| 1 | 场景 | 全程只有**桌面**与跷跷板；启动时车在桌面上，"地面"即桌面 |

## 1. 状态机

沿用现有枚举，不新增状态：

```
MS_IDLE --短按--> MS_ALIGN --对准--> MS_CLIMB --里程0.50m--> MS_BALANCE
       --10s稳定--> MS_RETURN --下板判据--> MS_ARRIVED
任意状态 --故障--> MS_FAULT --长按2s清除--> MS_IDLE
```

| 状态 | 动作 | 退出条件 | 超时 |
|---|---|---|---|
| `MS_IDLE` | PWM 0，LED 灭，等待 | 短按（<0.5 s） | — |
| `MS_ALIGN` | **只转不走**：`v=0`，`w = clamp(heading_kp·err)`，`err = wrap(board_heading − yaw_abs)` | `|err| < 2°` 且 `|ω| < 10°/s` 持续 0.2 s | 20 s → FAULT |
| `MS_CLIMB` | `v = 0.10 m/s` 直行，`w` 保持航向微调 | 里程 ≥ `climb_end_m`(0.50 m) | 25 s → FAULT |
| `MS_BALANCE` | `v = Balance_Update(pitch_rel)`（PID），`w=0` | `balance.stable`（容差内连续 **10 s**） | 90 s → FAULT |
| `MS_RETURN` | `v = −0.08 m/s`，`w` 保持航向；LED 闪 | 见 §2.3 下板判据 | 1.2 m 或 40 s → 停车 |
| `MS_ARRIVED` | PWM 0，LED 常亮 | 长按 → IDLE | — |
| `MS_FAULT` | PWM 0，LED 150 ms 闪 | 长按 2 s → IDLE | — |

**放弃的旧状态**：`MS_APPROACH`、`MS_SEEK`、`MS_PATH`、`MS_DOCK` 在统一流程中不再使用（`MS_APPROACH` 原来是"开到某个坐标点"，被"里程直行"取代）。

## 2. 关键判据

### 2.1 启动与基准重定义
- **短按**：`Board_Key()` 连续为 1 且总时长 < 0.5 s，松开触发；只在 `MS_IDLE` 有效。
- **长按**：连续为 1 达 **2.0 s** 立即执行 `App_Stop(0)` 回 `MS_IDLE`（运行中）或清除故障（`MS_FAULT` 中）。
- **基准捕获**（短按那一刻，一次性）：
  ```
  pitch_zero_deg = imu.euler_deg[pitch_axis]     // 等于"相对零位 = 0"
  ```
  **yaw 不参与清零**，保持绝对磁航向，否则无法对准固定板方向。
- 说明：GY953 的 Euler **roll/pitch 本身就是重力参考的绝对量**，所以"以当前为零位"实际是"把启动那一刻的姿态当作水平"。**因此桌面必须水平到 ±1°**（30 mm/1600 mm = 1.07° 是判据上限），否则平衡点会偏移。

### 2.2 对准与上板
- 对准误差 2° 来自 `key55 yaw_tol_rad`（0.035 rad ≈ 2.0°）。
- 板宽 300 mm、车宽约 190 mm → 单侧余量 55 mm；2° 误差在 0.5 m 行程上横向偏移 17 mm，安全。
- 上板里程 0.50 m 按"车距 A 约 0.30 m"设定：0.30 m 到斜板 + 0.20 m 上板。

### 2.3 下板判据（三段式）
```
后退开始 → [1] 出现 |pitch_rel| > 3° 并保持 ≥0.3 s → ramp_seen = 1
ramp_seen → [2] 出现 |pitch_rel| < 1.5° 并保持 ≥1.0 s → 判定到桌面 → 停车
兜底   → [3] 倒车里程 > 1.2 m 或持续时间 > 40 s → 强制停车（不报故障，按完成处理）
```
**为什么不能用"pitch=0"直接判**：平衡点 C 处 pitch 也是 0，必须用"先偏离、后回归"的序列。

### 3.3 `cal_flags` 的处理（**需确认**）
现有门槛：profile 3 需要 `CAL_PATH|CAL_ENTRY|CAL_BALANCE = 255`。但统一流程**不做**倾覆触发、**不做**自由起点，因此建议：

> 统一流程只要求 `CAL_PATH = 63`；`CAL_ENTRY`/`CAL_BALANCE` 不再参与判定。

理由：这两个位对应的行为（倾覆检测、灵活起点）在统一流程里不存在。`balance_sign` 的正确性改由 §7 的首次上板实测保证，而不是靠一个标志位。

## 6. 故障与安全

| 故障 | 码 | 处理 |
|---|---|---|
| IMU 超时 200 ms | 2 | 停车，LED 闪；长按清除 |
| 倾角 > `max_tilt_deg` | 7 | 停车，LED 闪；回允许姿态后长按清除 |
| 电机 1.5 s 无 FG | 8 | 停车；查接线 |
| FG 反馈断 | 3 | 停车 |
| UART 硬件错误 | 9 | 停车 |
| 对准 / 上板 / 平衡 / 下板超时 | 6 | 停车 |

**已删除的限制**：任务 1 的纵向/横向走廊（后退 5 cm、前进 1.25 m、`Course_Inside`）按用户要求全部移除，不再有位置类误停。

保留的安全：**下载/复位/暂停前必须断电机 12 V**（保持 RST 时电机会转，软件无法覆盖该时段）。

## 7. 未验证项与风险

| 项 | 风险 | 应对 |
|---|---|---|
| **`balance_sign`（key37）** | 符号反 → 正反馈 → 冲下板 | 首次上板用低 `max_v`（0.06）+ 手持架空先验方向；确认符号后再放开 |
| 桌面水平度 | 超 1° 则水平判据不达标 | 启动前用水平仪确认 |
| 磁航向常数 | Yaw 受电机/电池干扰，绝对精度未知 | 现场读一次；对准只在电机静止时进行 |
| 斜坡打滑 | 上板 0.50 m 里程可能不足或超 | 首次试跑记录实际位置，再调 `key45` |
| 爬坡能力 | 12 V 两轮能否上斜板未验证 | 首次空载试爬 |
| `stable_deg=1.0°` | 题目 30 mm 对应 1.07°，仍在判据内 | 若仍难以满足，最多放宽到 1.05° |

## 8. 实施顺序（每步可独立验证）

1. **参数固化 + 扩 `key45` 范围** → 下载后按 KEY 能自启动到 `MS_ALIGN`（先不求完成）。
2. **按键语义**（短按启动 / 长按 2 s 中断）→ 观察 `mode/state` 变化。
3. **基准捕获 + 纯转向对准** → 手转车身，看是否能稳定停在 ±2°。
4. **里程上板** → 架空/桌面直行 0.50 m 是否准确。
5. **`MS_BALANCE` + LED** → 手持摆动验证 PID 符号与方向（不上板）。
6. **10 s 保持与破平衡重计** → 手持破坏一次，确认计时复位。
7. **三段式下板** → 手动模拟斜坡 pitch 序列，验证判据。
8. **整轮联调** → 桌面 → 上板 → 平衡 → 保持 → 下板。
