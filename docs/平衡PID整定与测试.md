# 平衡 PID 整定与测试（试验版）

## 本版起始参数

PA0 自动装载的参数在 `App/Src/config.c` 的 `Config_ApplyMeasured()`：

| 参数 | 当前试验值 | 作用 |
|---|---:|---|
| balance_kp | 0.006 | 倾角比例响应 |
| balance_ki | 0.0003 | 积分响应，保留非零 |
| balance_kd | 0.012 | 角速度响应 |
| 两路 deadband / 前馈 | 0.35 | 速度 PI 的起始占空比 |
| min_duty | 0.35 | 非零电机输出的最低限幅 |

基于用户报告的最低可控占空比设置为 0.35，实际负载和方向仍需验证。PID 是未经实车整定的起点，不能保证阻尼或收敛；PID 单位见 configuration.md。轮速内环仍是 PI。本版不修改换向互锁、FG 异常告警或任务状态机。

## 方法 A：改默认值（每次需重新编译下载）

1. 在 VS Code 打开 `App/Src/config.c`，找到 `Config_ApplyMeasured()`，修改 `balance_kp`、`balance_ki`、`balance_kd`；数字后的 `f` 保留，例如 `.006f`。
2. 保存，点击 VS Code 的“生成”。下载或复位之前断开电机 12 V；下载 Debug 程序并运行。
3. 不从上位机加载覆盖参数时，短按 PA0 会在标定标志为 0 时装载这些默认值；起点 Pitch 每轮重新捕获。若此前已经通过串口加载参数，则以已加载值为准。

## 方法 B：上位机整定（每次上电或复位须重新发送）

1. 将车停稳并解除 ARM，连接上位机，在“参数与标定”点击“加载并逐项发送”，选择 `PC/config.task1-real.json`。该文件已与本版起始值同步。等待逐项 ACK，确认没有 `RANGE`/`LOCKED`/超时；最后 key 100 被发送。此 JSON 是输入记录，不是设备读回。
2. 在“参数 key”和“value”中输入下列键和值，逐项点“发送单项”并等待 ACK：34 对应 P，35 对应 I，36 对应 D。比如修改 P 为 0.005，填 key 34、value 0.005。需要调几项就分别发送几项。
3. **关键：每次修改 key 34/35/36 会清空 cal_flags。**全部 PID 项发送成功后，发送 key 100、value 63；确认 ACK 和界面 flags=3F。否则按 PA0 时自动加载默认参数，刚才的调整会被覆盖。63 沿用当前工程配置中的标定声明，并不证明物理标定已完成。
4. 确认姿态数据有效、现场条件满足，再短按 PA0 启动；运行时禁止更改参数。复位或断电后 RAM 参数丢失，须重新加载 JSON 并重新发送你调整的值。不要只发 key 100 和 PID：复位后其他参数仍可能是上电默认值。
5. 如需下次复用，在 VS Code 修改 JSON 中 `34`、`35`、`36` 的数字并保存，然后按步骤 1 完整加载；不要误以为上位机 JSON 等于设备参数读回。

## 调参次序

每轮只更改一个参数、记录原始帧和 CSV、观察实际运动再比较。建议先用当前值建立基线：

- P：若动作过激、过冲大，可小幅降低；若反应一直过弱，可以小幅增加。改变后仍需观察是否能跨过电机死区。
- D：反映角速度。只做小幅调整；符号、滞后和噪声可能使实际效果与直觉不同，若抖动或反向更激烈应停止并回退。
- I：保持较小。长期偏差消除慢时再小幅调整；持续来回、大幅超调或动作迟滞时优先检查积分积累。代码有积分限幅及跨零清理，仍无法保证不振荡。

不可根据一次 CSV 判定参数最优。FG 报警时位置不可信，不能以轨迹中点代替真实位置；使用录像和实际板端高度复核。保留 STOP 和现场独立电源切断措施；下载/复位/调试暂停前断电机 12 V，AUTO 与上位机断连后可能继续。不要在实际场地无人保护时测试。
