# F401_COURSE_SIMPLE 精简课程工程

这是独立工程；旧工程 `../F401_COURSE`、旧 Git 历史和用户数据均保留。重新编写了任务状态机和平衡 PID，复用了原工程的 STM32 初始化、板级驱动、IMU 查询、蓝牙协议、速度 PI 与换向保护；不是整套底层驱动从零重写。

## 主流程

PA0 短按：采集起始 Pitch 零位 → 对准板航向 → 双轮同步起步并持续修正航向上桥 → 检测首次翻板后 PID 平衡，Pitch ±1° 双轮输出零 → 稳定 10 秒 → 返回并指示。首次翻板检测在估计 X 达到 0.5 m 后启用：使用最近 500 ms 的新鲜 Pitch 帧，曾达到 +2° 且下降至少 2° 并持续 40 ms 时进入平衡。该阈值仅参考此前两轮数据，尚无新版本的实车验证。若无法检测翻板，小车会继续按上桥目标行驶；0.5 m 并不是停止位置，必须由人员监护并随时能够切断电机电源。任务 6 另选模式：首次平衡后保持，检测额外扰动后再次平衡并返回。任务 1 与 2 是以倾斜变化作为失衡估计；5 使用第 3/4 流程，由现场放置配重。课程 5/6 的现场衔接及计时仍需按老师规则确认，软件分支不等于比赛达标。任务 7 不在本精简工程中。

没有中点算法或翻板暂停。上板目标 `max_v=0.17 m/s`，67 mm 轮约 48.5 RPM，轮速目标限值 50 RPM，默认加速斜率 180 RPM/s、PWM 最大 100%；这不是实测最高速度或安全速度。PA0 默认平衡 PID P=.006 I=.0020 D=.028，保留用户调整值，允许上位机配置；参数在 `App/Src/config.c` 的 `Config_ApplyMeasured()`，上位机 JSON 位于 `PC/config.task1-real.json`，两者不一定相同。平衡阶段每轮目标速度上限按角度从 0.025 到 0.070 m/s 变化，向水平靠近时使用 0.40 s 的 Pitch 趋势预测提前降低上限；常量在 `App/Inc/course.h` 的 `BALANCE_SPEED_*`、`BALANCE_SLOW_ANGLE_DEG`、`BALANCE_LOOKAHEAD_S`。该策略和参数尚未实车验证，速度目标不是实际轮速或主动制动。PWM 最低输出 .35 是用户的测试值，负载下仍需确认。

## 启动与调试

1. VS Code“文件→打开文件夹”，选择本目录 `D:/STM32Dev/F401_COURSE_RETURN_WORK_2026-10-30/projects/F401_COURSE_SIMPLE`。选择 Debug、点击生成，调试配置选择 `STM32Cube: Course Simple ST-Link`。烧录文件 `build/Debug/F401_COURSE_SIMPLE.elf`。不要使用旧工程的 ELF。
2. 每次下载、复位或暂停调试前断开电机 12 V；旧硬件在 RESET 时可能高速转动。控制板独立供电并保持共地。先架空核验方向、停转和急停；此后在受保护的场地测试，保留能独立切断 12 V 的开关。AUTO 断开蓝牙也可能继续运行。
3. PC 双击 `PC/启动上位机.cmd`，选蓝牙对应串口连接 115200。先确认 IMU age 小且 Pitch/Yaw 连续更新，双轮静止。上位机的任务选择和 PA0 是不同入口：PA0 默认任务 3/4；任务 6 请在“参数与标定”加载 `PC/config.task1-real.json` 并等待 ACK，再在控制区选任务 6 启动。请在启动前确认 Pitch 零位和参数；JSON 是输入记录，不是设备读回。PA0 和上位机启动都会捕获当前 Pitch 为零位，并以启动位置作为相对距离零点。
4. 先低风险架空验证方向和停止，再从低风险条件开始按现场规则测试。录制视频并导出本轮 CSV；任何离板趋势或异常立即人工断动力。首次实测不要直接视软件构建通过为可全速比赛。

FG 是单路速度反馈，方向依靠指令假设；打滑、错脉冲、运动时失联可使 0.5 m 和返回估计失准。IMU 姿态不是全局定位，无法保证任意位置起始、40mm 定位圈或场地无误判。陀螺仪安装姿态、航向、坡板响应、任务6扰动判断及上板/返回距离都必须实车核查。`pose_valid=0` 的轨迹不能作为位置证据。PID 参数与速度需根据实际负载调试。
